# Linter & Code Style — правила для кода Mirro

Как писать код в этом проекте, чтобы линтер был доволен и код оставался структурным.

## Правила (в порядке важности)

### 1. Структурное программирование
- **Один выход из функции**: у функции один `return` в конце. Ранние выходы заменяй на
  переменную-результат + `break`/`if`.
- **Без `continue`**: вместо него — инвертированное условие (`if x not in ...:`).
- Функции **2–3 строки** по возможности; большие разбивай на helper'ы с говорящими именами.
- Функция делает одно действие. Название отражает действие (глагол + дополнение).

### 2. Именование
- Функции/методы: `snake_case`, глагол первым (`build_index`, `_match_triple`).
- Приватные helpers: с `_` в начале (`_clean`, `_step`).
- Внутренние мини-функции-однострочники можно без `_`, если это публичный интерфейс модуля.
- Константы: `UPPER_SNAKE` (`SPIKE_THRESHOLD`, `_PHASE`, `BASE`).
- Логические переменные — флаг `is_...` / `has_...` (`is_pending`, `is_novel`).

### 3. Декораторы и ООП
- **Декораторы** используем экономно и осознанно: `@staticmethod` для функций без self,
  `@classmethod` для альтернативных конструкторов. Кастомные декораторы — только если
  это реально переиспользуемая логика (кэш, отладка), и с docstring.
- Класс — это связка **данных + действий над ними** (пример: `KnowledgeGraph`,
  `DialogueMemory`, `Neuromodulators`). Не плоди классы с одной функцией — там модульная функция.
- Методы: один return в конце, без side-эффектов кроме явного имени (`save`, `learn`).
- `__slots__` — если много однотипных объектов (как `Node` в графе) — экономит память.

#### Пример переиспользуемого декоратора (кэш)
Когда одна и та же логика нужна на многих функциях — выносим её в декоратор:

```python
import functools

def cached(cache=None):
    """Кэширует результат функции по аргументам. Один return: обёртка."""
    store = cache if cache is not None else {}
    def deco(fn):
        @functools.wraps(fn)
        def wrapper(*args, **kwargs):
            key = (args, frozenset(kwargs.items()))
            if key not in store:
                store[key] = fn(*args, **kwargs)
            return store[key]
        return wrapper
    return deco

# исп.:
@cached()
def approx(x):
    return x * 3.14
```

Правила для декоратора:
- один `return` в самой функции и в обёртке;
- DOC-string у обёртки через `functools.wraps`;
- декоратор ничего не печатает (side-эффект только через возврат);
- кэш-декоратор — чистая функция, без глобального состояния кроме `store`.

### 4. Импорты
- Порядок: стандартная библиотека → сторонние → локальные модули (пустая строка между блоками).
- Импорт модулей `algos.*` внутри функции (`lazy import`) — приемлемо в ядре из-за
  тяжёлого индекса, но в обычных модулях ставь импорты наверх.
- Избегай `from X import *` — явные имена.

### 5. Docstring
- Каждая публичная функция: `"""Короткая суть. Один return: тип."""`.
- Указывай в docstring «Один return: ...» — чтобы соблюдать правило одного выхода.

### 6. Прочее (flake8/ruff ожидают)
- Максимум строки ~ 110 символов.
- Без пробелов вокруг ключевых= в вызовах функций (`weight=1.0`), но с пробелами в сравнениях.
- Пустые строки: 2 между top-level функциями, 1 между методами класса.
- Без неиспользуемых импортов; без `print` в логике (кроме `__main__`/отладки).

## Запуск проверки

```bash
# ruff (если установить):
pip install ruff
ruff check algos/ core/ scripts/ tools/ tests/

# flake8 (альтернатива):
pip install flake8
flake8 algos/ core/ scripts/ tools/ tests/ --max-line-length=110

# наш локальный DRY-check (без зависимостей):
python tools/check_duplicates.py
```
